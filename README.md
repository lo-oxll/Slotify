# وقتي — منصة متكاملة: حجز مواعيد + توظيف

HTML + CSS + JS فقط، بلا بناء ولا Node. كل الملفات في جذر واحد وتعمل على GitHub Pages.

## كيف تتكامل الأجزاء
حساب واحد لكل مستخدم بدور واحد، وكل شيء مترابط:

| الدور | ماذا يفعل | صفحاته |
|---|---|---|
| **فرد** (عميل / باحث عن عمل) | يحجز خدمات، وينشئ سيرة ذاتية موحّدة، ويتلقى ترشيح الوظائف، ويتقدّم | `home` `services` `book` `bookings` `cv` `jobs` `job` |
| **شركة / نشاط** | تضيف خدمات وتستقبل حجوزات، وتنشر وظائف ويرشّح لها النظام المتقدمين | `business` (نظرة عامة · حجوزات · خدمات · وظائف · ملف) |
| **زائر** | يتصفح الخدمات والوظائف وصفحات الشركات بلا حساب، ويحجز كضيف | `index` `services` `jobs` `job` `b` |

- صفحة الشركة العامة `b.html?s=اسم` تجمع **الخدمات القابلة للحجز** و**الوظائف المتاحة** ونبذة عن النشاط.
- روابط الوظائف تُشارَك (`job.html?id=…`)؛ إن لم يكن الزائر مسجّلًا يُوجَّه للدخول ثم إنشاء السيرة ثم يعود لنفس الوظيفة تلقائيًا.
- **السيرة الذاتية** (`cv.html`): نموذج واحد موحّد لكل الأفراد.
- **المطابقة** (`match.js`) في الاتجاهين: وظائف مناسبة للفرد، ومرشحون مقترحون لكل وظيفة.
  الدرجة = مهارات 55% + خبرة 20% + مؤهل 10% + مدينة 10% + مسمى 5%، وغير المهارات لا تُحتسب كاملة بلا توافق مهارات. الترشيح من 30% فأكثر.
- **الخصوصية:** رقم الفرد لا يصل للشركة إلا بعد قبول حجزه أو عند تقديمه على وظيفة (أو إن وضع وسيلة تواصل بنفسه). السيرة يمكن إخفاؤها.

## النشر على GitHub Pages
1. احذف الملفات القديمة من المستودع وارفع كل ملفات هذا المجلد إلى **الجذر**.
2. Settings → Pages → Source: فرع `main` والمجلد `/ (root)`.

## وضعان
- **تجريبي (الافتراضي):** `config.js` فارغ، فيعمل كل شيء فورًا والبيانات داخل متصفحك فقط (localStorage). فيه صالون ووظيفة تجريبيان.
- **حقيقي (مشترك بين الجميع):** عبّئ `config.js` بإعدادات Firebase:
  1. أنشئ مشروعًا وقاعدة **Firestore**.
  2. Authentication → فعّل **Email/Password** و**Google** و**Anonymous**.
  3. Project settings → Your apps → Web: انسخ الإعدادات إلى `config.js`.
  4. Firestore → Rules: الصق `firestore.rules` ثم Publish.
  5. Authentication → Settings → Authorized domains: أضف `USERNAME.github.io`.

## مجموعات البيانات (Firestore)
`users` · `businesses` · `slugs` · `services` · `bookings` (+ `contact`) · `busy` · `cvs` · `jobs` · `applications` · `errors`

## بنية الملفات (كلها في الجذر)
- **صفحات:** `index` `login` `home` `services` `book` `bookings` `cv` `jobs` `job` `business` `b` `terms` `privacy` (.html)
- **منطق:** `common.js` (جلسة، ترويسة، حماية، تقديم) · `slots.js` (المواعيد) · `match.js` (السير والمطابقة) · ملف JS لكل صفحة
- **الخلفية:** `firebase.js` يختار تلقائيًا بين `fb-real.js` (Firebase) و`fb-local.js` (تجريبي) بحسب `config.js`
- **أخرى:** `style.css` `sw.js` `manifest.webmanifest` `icon.*` `firestore.rules`

## حدود معروفة
- الترشيح يحلل حتى 300 سيرة ظاهرة و300 وظيفة؛ الأكثر يحتاج فهرس بحث (Algolia وغيره).
- المطابقة بالكلمات، فلا تعرف أن «برمجة» قريبة من «تطوير» إلا إن كتبهما الطرفان.
- لا بريد/إشعارات خارجية (يحتاج خادمًا)، والتنبيه داخل لوحة الشركة فقط.
